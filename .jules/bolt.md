## 2024-05-18 - Master Toggle Concurrency Bottleneck
**Learning:** This codebase uses a global mutex and synchronous JSON file writing for configuration persistence. When the master toggle triggers `Promise.all` to send concurrent `PUT` updates for N hosts, the backend receives N requests simultaneously. Each request locks the mutex, modifies the list, and writes the entire host list to disk. This causes O(N^2) lock-contended disk writes, severely degrading both API responsiveness and I/O performance for large numbers of hosts.
**Action:** Always batch update requests on the client side into a single bulk update API call when modifying multiple records simultaneously, especially when the backend persistence mechanism isn't designed for high concurrency (e.g., synchronous file writes under global locks).
